# 密码库部署与安全说明

## 启动

密码库依赖现有的 Glosc AI SSO、PostgreSQL 和 Redis。先在 SSO 控制台配置授权码客户端，设置 `SSO_CLIENT_ID`、`SSO_CLIENT_SECRET` 和精确匹配的 `SSO_REDIRECT_URL`。再运行 `openssl rand -base64 32` 生成一次 `VAULT_MASTER_KEY`，将其与数据库备份分开保管。启用 SSO 但未配置该密钥时，服务端会拒绝启动；更换或丢失它会使现有密码库无法读取。生产环境必须使用 HTTPS，并正确配置 `JWT_SECRET` 与 Secure Cookie。

开发环境访问 `/`，登录后创建密码库。用户的安全 Key 只在当前浏览器内存中使用，不会发送到 API；每次刷新或在新设备登录后都要重新输入。创建和每次更换 Key 后都会生成新的恢复码，仅展示一次。安全 Key 和恢复码都丢失时，无法恢复旧密码，只能销毁旧库重建。

## 加密边界

- 浏览器使用 Argon2id 从安全 Key 派生包装密钥，AES-256-GCM 加密随机数据密钥；恢复码有独立的盐与包装。每条凭据的名称、网址、用户名、密码、备注和收藏状态都由数据密钥加密。
- 服务端为每个用户生成独立的第二层密钥，用 `VAULT_MASTER_KEY` 保护它；第二层密钥从不发送到浏览器。服务端仅能解开外层密文，不能读取凭据明文。
- 换 Key 时浏览器生成新数据密钥，重新加密全部凭据与包装，API 在数据库事务中按版本号原子替换。新恢复码取代旧恢复码；历史数据库快照不受此次更换影响。
- 已解锁的明文只保留在浏览器内存；刷新、离开密码库、退出登录或闲置十分钟会锁定。受感染的浏览器或恶意扩展仍可读取解锁后的明文，因此密码库不加载第三方脚本或字体。

## 导入导出

支持 Chrome/Edge/Firefox CSV、Bitwarden CSV/JSON、1Password CSV/1PUX 的登录条目。1PUX 附件与其他类型不导入；导入文件在浏览器本地解析并预览，只有再次加密后的记录上传。单文件限 20 MB，单次最多 5000 条登录凭据。

加密备份使用独立口令，可在新部署中导入，不依赖原服务端密钥。明文 CSV 仅供迁移，下载前二次确认；请妥善删除迁移后的文件。导出内容不会上传或保存在服务端。

## 验证

运行 `cd server && go test -race ./... && go vet ./...`、`cd web && npm test && npm run build`。PostgreSQL 集成测试需另外设置 `VAULT_TEST_DSN`，并仅指向隔离的测试数据库。
